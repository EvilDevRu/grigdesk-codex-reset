# API и события

Префикс — `/api/ext/codex-reset`. Все маршруты защищены общим доступом GrigDesk;
при выключенном плагине ядро возвращает `404 plugin_disabled`.

| Маршрут | Поведение |
|---|---|
| `GET /status` | Снимок памяти, без ожидания сети. Дополнительно содержит `pluginId` и `api: 1`. |
| `GET /provider-usage?providerId=codex` | Строки существующей всплывашки; для другого исполнителя `resources: []`. |
| `GET /signal` | Чтение с учётом часового кэша, объединения запросов и паузы после ошибки. |

Пример формы ответа `/signal` с условными данными:

```json
{
  "providerId": "codex",
  "source": "codexreset.org",
  "homepage": "https://codexreset.org/",
  "fetchedAt": null,
  "checkedAt": null,
  "stale": true,
  "error": null,
  "lastReset": null,
  "chance24h": null,
  "chance48h": null
}
```

При наличии истории `lastReset` содержит `at`, `title`, `scope`, `sourceLabel`
и `sourceUrl`. Даты — ISO UTC. Поле `sourceUrl` может быть `null`, если ссылка
не прошла проверку. Оценки — числа 0–100 либо `null`; ноль является оценкой,
а не признаком отсутствия данных.

Ошибка источника возвращается в снимке с HTTP 200, чтобы читатель получил
предыдущие данные и их состояние. Возможные коды перечислены в
[контракте источника](source.md). `fetchedAt` — момент последней успешной загрузки,
`checkedAt` — последней попытки. После перезапуска снимок собирается заново.

При изменении снимка `options.core.emit('signal', snapshot)` публикует событие:

```json
{
  "pluginId": "codex-reset",
  "event": "signal",
  "data": { "providerId": "codex", "source": "codexreset.org" }
}
```

Здесь `data` сокращено для примера; в событии приходит полный снимок `/signal`.
Доставка идёт через общий SSE GrigDesk под именем `plugin-event`.
Получатель сначала читает снимок и обрабатывает последующие изменения.
Плагин не создаёт отдельный SSE-поток, страницу или уведомления.
Всплывашка использует JSON-ресурсы `/provider-usage`, общий UI GrigDesk
и тумблер размещения. Русские и английские тексты едут с ресурсами;
ссылки остаются HTTPS-ссылками источника.
Сводка последнего сброса содержит давность относительно момента запроса
(например, «5 часов назад» / «5 hours ago»), даже если снимок берётся из кэша.
Дата `lastReset.at` в `/signal` и `/status` остаётся в формате ISO UTC.
