# Подготовка публикации

Проект публикуется в приватном репозитории `EvilDevRu/grigdesk-codex-reset`.
Git-репозиторий разработки не является установленной копией плагина.
Публикация выполняется отдельным явным действием владельца.

## Перед выпуском

1. Синхронизируйте версии `plugin.json`, `package.json` и запись в `CHANGELOG.md`.
2. Запустите тесты и проверку поставки:

   ```bash
   GRIGDESK_SOURCE_ROOT=/absolute/path/to/grigdesk npm test
   npm run check:release
   npm run pack:release -- /absolute/path/to/artifacts
   ```

3. Просмотрите README, иконку и документацию. Ссылка на релиз в README должна
   соответствовать выпускаемой версии; доступ к приватному репозиторию указан в установке.
4. Убедитесь, что `git status` содержит только ожидаемые файлы. Рабочие секреты,
   локальные пути и сохранённые страницы стороннего сайта в поставку не входят.

Пакет не предназначен для npm registry: `private: true` защищает от случайного
`npm publish`. GrigDesk устанавливает его непосредственно из Git.

## Репозиторий и тег

Следующие команды являются инструкцией для будущей публикации и не выполняются
при проверке или упаковке. Они создают приватный репозиторий и отправляют код:

```bash
gh repo create EvilDevRu/grigdesk-codex-reset --private --source=. --remote=origin
git add .
git commit -m "Initial Codex Reset plugin"
git tag -a v0.1.0 -m "Codex Reset 0.1.0"
git push -u origin main
git push origin v0.1.0
gh release create v0.1.0 --verify-tag --title "Codex Reset 0.1.0" --notes-file CHANGELOG.md
```

Если remote или репозиторий уже существует, используйте его вместо повторного
создания. Стабильный тег обязан указывать на проверенный коммит с той же версией
в манифесте. Архив и соседний `.sha256` можно добавить к GitHub release.
Для каталога GrigDesk нужны URL репозитория, тег, полный SHA, описание и иконка;
добавление в каталог — отдельная операция.

## Иконка

`docs/assets/codex-reset.svg` — собственный знак в стиле README других плагинов:
синяя обводка, контур 24×24, круговая стрелка вокруг часов. SVG содержит `title`
для доступности, не загружает внешние ресурсы и не использует шрифты или скрипты.
Иконка относится к оформлению репозитория; добавлять `nav` для неё не нужно.
